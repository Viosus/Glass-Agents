# 项目架构说明

## 项目
Glass Agents = 对流钢化炉 · 本地化多 Agent 调参系统。目标：模仿老师傅，按"这炉玻璃的状况"产出工艺参数。

## 当前阶段
五阶段数据飞轮：
- A 冷启动搭 Teacher（规则 + 指标 + 大模型，**无训练**）
- B 产数据（专家复核出标签）
- C 训练 Student（**唯一真正训练**）
- D 验证
- E 部署 + 持续回灌

**当前位置：阶段 0「评测靶子」起点** —— 护栏与最小代码刚起步，暂无现场数据。

## 模型架构（已敲定：多头核心，不做 6 模型拼接）
按"计算类型"切，而非按 6 个 agent：
- **确定性层（代码，0 训练）**：质量指标、硬约束、设备损耗、厚度-时长/对流规则表 —— 大半 agent 落这。
- **感知小模型（可选）**：图像→特征里真正要学的部分；可先用经典 CV / 指标顶着。
- **一个多头核心模型（唯一要训练）**：共享编码器 + 参数头 / 质量头 / 能耗头 / 归因头。
- **安全闸门永远在模型之外**：模型出的参数仍须过 `tools/constraints.py`。
- **为什么多头帮小数据**：稀缺专家标签只学"最后一公里"决策；"读懂这炉玻璃"交给海量免费的实测质量/能耗标签训共享表示。

## 仓库结构
- `tools/` — `constraints.py`（硬约束安全闸门）、`metrics.py`（X0.95 / IsoT / CCP + 评估区域掩膜）。纯函数 + 单测。
- `config/` — `grading.yaml` / `thresholds.yaml` / `ccp_reference.yaml`，**数据驱动，限值禁硬编码**，由 tools **运行时按需读取**。
- `tests/` — pytest，覆盖临界值；`pytest.ini` 设 `pythonpath=.`。
- `.claude/skills/` — `glass-metrics`、`constraint-check`（自动发现）。
- `.claude/hooks/` — `pre_commit_gate`（提交硬闸门）、`posttool_tests`（编辑后快速反馈）。
- `docs/` — 项目笔记、INSTRUCTION 运行手册、数据填写说明。
