# 现场检测装置 · 软件功能改善方案

> 依据：`docs/现场检测装置软件需求.doc`（2026-07-10）。业务定位：联合上海建科所幕墙检测中心
> 推出「玻璃幕墙视觉舒适性」现场检测，展示公司专业性、带动检测设备推广。
> 设想流程：检测装置拍摄图像 → 现场电脑拼接处理 → 数据传手机出结果 → 关注公众号得分析报告。
> 载体决策（2026-07-10 拍板）：手机端做进**现有明之言微信小程序**，加「幕墙检测」模式与
> 工厂质检共存，一套代码、同一打分服务器。

## 二、P0 已落地内容（明之言小程序，2026-07-10）

- **模式切换**：首页「工厂质检｜幕墙检测」segment，工厂模式流程零变化；模式记忆在本机。
- **检测信息卡**（幕墙模式）：建筑名称、📍一键定位（wx.getLocation，失败可手填降级）、
  玻璃宽×高 mm、膜系、结构；随上传以表单字段附带（服务端当前忽略，P1 落盘）。
- **检测位置九宫格**：3×3 点位（左上…中心…右下），选中点位后拍照归入该点位，格子角标显示
  已拍张数；同一片玻璃多点位累积（会话制），「重新开始」清空换下一片。
- **综合得分**：完成检测 → 结果页头部「幕墙综合得分卡」= Σ(点位均分×位置权重)/Σ权重，
  逐点位列表 + 权重口径明示；单点位多张取均值；单张照片得分取服务器返回 total_mean。
- **检测记录页**：本地保存历次检测摘要（幕墙：建筑/综合分/逐点位；工厂：张数/片数/判废数），
  上限 200 条自动修剪，可删除；**只存文本摘要不存任何照片**。
- 失败重试、逐片复核反馈、离线先拍后传等既有链路在幕墙模式下全部沿用。

## 二·五、追加落地（2026-07-10 下午）

- **本地打分（离线估算）**：fringe_scoring 全管线纯 JS 移植进小程序 Worker
  （`workers/scoring/algo.js`），幕墙模式开关启用，无服务器也能单片算分（约 5–30 秒/张）。
  数值对照（两张真实应力斑图）：与 Python 原版全部指标相对偏差 ≤7×10⁻¹²、判斑掩膜逐像素
  一致——**算法等价**；实际差异只来自手机图像链路（canvas 解码/缩放、长边 2000px 封顶），
  故 UI/记录一律标「本地估算」。范围=仅单片（玻璃充满画面）；工厂整床多片仍走服务器。
  参数快照 `utils/local_config.js` 抄自服务器 config（2026-07-10），服务器改参数须手工同步。
- **公众号软门槛**：首次使用进引导页（公众号二维码占位图 `assets/mp_qrcode.png`，
  真图到位直接覆盖）+「我已关注」自确认放行。真校验（UnionID+服务端）已列入
  接口需求_现场检测.md 第 3 节，属 P1。

## 二·六、功能架构重划（2026-07-10 晚，用户拍板）

原「工厂模式 vs 幕墙模式」概念作废，小程序重划为**三大独立功能**：

1. **应力斑检测**：拍照/相册 → 六指标打分，**联网测算（服务器，支持整床多片）/
   本地测算（手机 Worker，单片）** 二选一；原有打分链路全部归此功能。
2. **幕墙检测**：现场拍摄 + 九宫格选位，**固定本地计算**——幕墙专用算法（弓波形/光畸变等）
   未拿到，当前**只有采集 UI 与算法接口 stub**（`utils/curtain_algo.js`，契约见
   接口需求_现场检测.md §5），不出任何检测值；完成采集写本地采集单记录（标'待算法'）。
   原「按点位用应力斑分数合成综合分」的做法随重划移除（那是两个功能的混淆）。
3. **远程操控**：手机对算法电脑**方案级调参**（切激活方案/判废线/六指标权重/参考值，
   底层判斑参数只读）+ **数据调取**（历史列表/标注图）。服务端四端点契约见
   接口需求_现场检测.md §4（转 server 维护方），未实现前 UI 优雅降级。

首页改为三功能入口 + 服务器设置；检测记录页支持应力斑批次与幕墙采集单两类记录。

## 二·七、账号登录制度（2026-07-12，本 session 直写 server 获用户授权）

## 二·八、数据调取 + 一人多账号（2026-07-13，用户拍板）

**背景**：账号绑仪器采用「一人多账号」路线（每台仪器一个账号，云端名册逐台发密钥）；
同时两端手机客户端要能从打分电脑拉取已测数据。

**已落地**：
1. **服务端（server/accounts.py）**：解除 `wx_openid` 唯一约束（旧库自动表重建迁移，
   建新表→拷数据→DROP→改名，防 sessions 外键引用被 RENAME 污染）；wx-login 升级两步
   协议——多绑定账号时对声明 `supports_choice` 的客户端返回 `need_choice+accounts` 候选
   （不发 token），选定后带 `username`+新 code 重调；旧版客户端兜底直登 last_login 最新
   账号（防旧版把无 token 响应存成登录态）。账密登录顺手绑定不再检查 openid 占用
   （借手机登录会绑走微信——知道密码≈授权，误绑走 `unbind-wx`）。
   冒烟：旧库迁移/wx-login 全分支/权限矩阵回归全绿。
2. **小程序**：`utils/auth.js` 改多账号存储（accountList+活跃下标，老键一次性迁移+镜像
   写回防版本回滚），对外签名不变、业务页零改动；首页账号卡加「切换 / 添加账号」
   （ActionSheet）与微信多账号内嵌选择态；新页 `pages/histdata`「数据调取」= 首页第 4
   入口（pro 门禁）：/api/history 分页列表 + 页内六指标详情 + 标注图预览。
3. **Flutter App**：新增 `lib/auth.dart` 最小账号登录（prefs 键 acctServer/acctToken/
   acctProfile 与直连 baseUrl/token 严格分离，gls1 令牌优先）；首页第 4 卡「数据调取」→
   `lib/data_page.dart`（账号登录｜直连令牌两模式）→ 复用 RemoteRecordsPage（加可选
   api 注入，远程操控入口行为不变）。flutter analyze 零告警。
   Flutter 多账号切换本轮不做（本地多存 (token,profile) 即可，契约无阻）。

**契约详情**：明之言小程序/接口需求_现场检测.md §6.2（微信多绑两步协议）、§6.3（数据调取）。

## 三、风险与待定项（如实列，不放行）

1. **现场图像与算法口径适配未验证**：fringe_scoring 按工厂暗场偏光整床照片标定；检测装置
   现场图像（拼接后）能否稳定检出玻璃区域、灰度统计口径是否一致，需装置样图实测。检不出片
   时服务器按 422 明确拒绝（不出瞎分）。→ 拿到装置样图后先跑适配验证。
2. **位置权重无真值**：需求只说「越中间权重越高」，未给数值。已做成 config 数据结构
   （`config.js POSITION_WEIGHTS`），当前为示意值（中心1.0/边0.8~0.9/角0.6，与服务器
   `app.field_mode.position_weights` 同口径），UI 标注「示意值待标定」。
   → 待与建科所标定后填入（小程序 config.js 与服务器 yaml 两处同步），代码不动。
3. **弓波形/光畸变**：两个指标当前整条链路（设备→算法→展示）都不存在，属新专项，不在小程序
   范围内解决；小程序只保证「数据来了能接」。
4. **wx.getLocation 资质**：开发者工具/测试号可用；正式发布需在小程序后台开通对应类目并配置
   隐私协议（app.json 已按规范声明 permission + requiredPrivateInfos）。
5. **公众号报告**：需公众号主体与模板设计，建议待 P1 历史接口就绪后由报告数据直接生成。

## 四、分期路线

- **P0（已完成）**：小程序端信息采集/点位权重合成/本地记录，纯客户端，不动 server。
- **P1（服务端，转 server 维护方）**：/api/analyze 落盘幕墙元数据；GET /api/history 历史列表
  （小程序记录页可切「本机/服务器」两个数据源）；报告导出数据结构。
- **P2（专项立项）**：弓波形/光畸变算法与装置数据接入；15 米反射倒影模拟渲染；公众号报告管道。
