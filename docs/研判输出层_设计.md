# 研判输出层（advisor）· 设计

> 代码：`advisor/`　|　配置：`config/{energy,maintenance,loading,attribution}.yaml`　|　测试：`tests/test_advisor.py`
> 需求源：《钢化炉多AGENT分层AI调参小模型架构（讨论稿）.doc》§3.1 / §4.2　|　建立日期：2026-07-02

## 1. 为什么有这一层

对照架构讨论稿检查（2026-07-02）：§4.2 要求的六项研判输出中，能耗方案、维保建议、摆炉方案
**没有出口**，且已有输出（参数/安全/应力斑）散落各模块、没有统一装配。本层把六项输出装配成
一个 `AdvisoryReport`，**每节自带可判定状态**——缺真值/数据的节如实 `cannot_determine` 并列明
缺什么（对应《信息需求清单》编号），真值到位（填 yaml）即点亮，无需改代码。

结构说明：不照搬讨论稿的"6 AGENT"（项目已定按计算类型切的多头核心架构）；本层对应讨论稿
"大模型研判层"的**输出装配职责**，数值全部来自确定性模块，LLM 不进本层（规则 > AI）。

## 2. 输出契约 ↔ 讨论稿映射

| 讨论稿要求 | AdvisoryReport 节 | 承载模块 | 点亮条件 |
|---|---|---|---|
| §4.2-1/2/3 全套温度/对流/摆动/时长参数 | `params: ParamsAdvice` | 上游产参（teacher_loop/多头核心）→ 本层强制过 `constraints.validate` | 上游产参 +（终态）A3-A6 真值让闸门可放行 |
| §4.2-2 对流风温、风机启动逻辑 | `params.params.convection_temp / fan_startup_logic`（可选字段） | schemas/process_params + tools/constraints | 字段语义与约束规则：E5 |
| §4.2-4 最优摆炉生产方案 | `loading: LoadingAdvice`（片数/排布/间距，grid 策略） | `advisor/loading.py` | E3（炉床尺寸+片间距） |
| §4.2-5 / §3.1.3 能耗值、**降参空间**、最低能耗方案 | `energy: EnergyAdvice`（估计值；降参空间与方案同源，缺口在 plan_note 点名） | `advisor/energy.py` | 估计值：E1 系数；降参空间与方案：E1+A3-A6+质量模型 |
| §4.2-6 / §3.1.4 老化度、**精准维保时间**、检修计划 | `maintenance: MaintenanceAdvice`（逐部件老化度 + `est_hours_to_service` 线性外推剩余小时 + 检修清单） | `advisor/maintenance.py` | E2（权重/额定值）+ B4（运行数据） |
| §3.1.2 缺陷→工艺归因 | `attribution: AttributionAdvice`（violations 透传 + 映射表规则） | `advisor/attribution.py` | E4 映射表（D3 类目）；分区定位另需 A9 |
| §3.1.5 人工经验复刻（调参习惯/幅度/顺序/修正逻辑） | —（**不设运行时输出**，非缺口） | 参数头训练承载：老师傅标注表 → 数据飞轮 → 多头核心，"复刻"落点是模型权重而非报告字段 | 数据门（200 份标注）+ N4 真训练 |
| §3.1.1 光焦度/弓波输出特征 | `optical: OpticalFeatureSlots`（插槽，未接恒 None） | schemas/inputs.py | B 组图像源硬件 + 算法迭代 |
| §2.5 环境辅助输入 | `environment: EnvironmentInput` | schemas/inputs.py | 现场采集接入（B4 同族） |

应力斑分数不在本层计算：由外部检测软件评好送达（`MetricRecord.fringe_score_0_100`），
作为 `quality_signals` 喂给归因线。

## 3. 使用方式

```python
from advisor import advise, report_to_text

report = advise(
    params=suggestion.params,          # 上游 Teacher/多头核心产参（可缺）
    baseline=baseline_params,          # 基准配方 → Δ 信号进归因
    usage=equipment_usage,             # 设备运行数据（B4 到位前可缺）
    quality_signals={"fringe_score_0_100": 78.5, "centrality": 0.62},
    glass_length_mm=900, glass_width_mm=600,
)
print(report_to_text(report))          # 确定性中文摘要（不调 LLM）
```

- 未传 `check` 时本层**自动**对 params 过安全闸门——出参必过闸门的铁律在装配层兜底。
- 测试/演示可经 `configs=` / `refs=` 注入配置与合成系数；`refs` 注入的产出一律
  `is_calibrated=False`（同 CCP 模式，绝不当真值下发）。

## 4. 诚实边界（本期明确不做）

- **降参空间与最低能耗方案搜索器**（§3.1.3 后两项，同源）：需 A3-A6 硬约束真值（当前闸门
  对任何参数全拦，无可行域）+ 质量预测模型；`plan_note` 如实点名两者，接口留在
  `advisor/energy.py`（真值到位先补降参空间，再补方案搜索）。
- **条状/块状形态分类**（§3.1.1）：应力斑形态分类属 fringe_scoring（外部交付件）的
  后续迭代，不在本层；当前分布信息由 centrality/掩膜承载，"条状 vs 块状"类别输出待
  真实图形态样本再定义。
- **光焦度/弓波算法本体**：无图像源，只建插槽字段（`optical_power_mdpt`/`bow_height_mm`/
  `wave_amplitude_mm`），防闭门造车。
- **疑似分区定位**：`Suspect.zone` 恒 None 直到 A9 二维邻接关系到位。
- **对话壳接线**：dialogue.py 并行迭代中，advise() 接入下一轮做。

## 5. 与讨论稿的有意偏离（保留，不视为缺口）

| 讨论稿 | 本项目 | 理由 |
|---|---|---|
| 五层/6-AGENT 结构 | 确定性层 + 多头核心 + LLM 角色层 + advisor 装配 | 按计算类型切分更利小样本（架构说明.md） |
| 工艺规则"蒸馏固化进小模型" | **规则永不进权重**，闸门永在模型外 | 安全可审计（安全与合规要求.md） |
| 30–50 组样本即可初训 | 数据门 200 份 | 统计上更稳（标注表拍板） |
