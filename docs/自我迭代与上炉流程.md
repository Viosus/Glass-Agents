# 自我迭代与上炉流程（原理说明）

> 回答两个问题：①agent 的自我迭代靠什么原理成立；②装到一台钢化炉上后，要经历什么过程才算"可用"。
> 面向新人与工厂方的原理版；操作命令级 runbook 见《同步与自我迭代》，待补信息见《信息需求清单》。
> 更新日期：2026-07-02

## 1. 自我迭代的原理

自我迭代**迭代的是数据和权重版本，不是代码**。环路：

```
生产 → 老师傅标注/复核(真值) → ingest 入库(带炉子身份)
   ↑                                      ↓
出炉实测回灌 ← 人确认后应用 ← 建议(过闸门) ← 重训 → 版本门 → 晋级/激活
```

支撑它成立的四条原则：

### 1.1 全量重训，不做在线增量
每次迭代都在"迄今全部真值样本"上重新估计参数头——统计上是基于扩大样本的重新最小二乘，
不是递推滤波。小样本表格回归下全量重训只要几秒，换来：无灾难性遗忘、无漂移积累、
每个版本可完整复现（checkpoint 带特征/Δ 契约指纹，见 `training/train_param_head.py`）。

### 1.2 版本门是棘轮，迭代单调不退化
新模型晋级须同时过三关（`tools/model_registry.promote`）：
- 验证集 MAE 不差于现任版本 ×(1 + `gate.regression_tolerance`)；
- 解码出参**零违规**（`evaluate_param_gate` 内强制过 constraints）；
- 训练样本量 ≥ `min_train_samples`。
任何一关不过留在候选区。防的是"自我迭代变成自我退化"——没有棘轮，一批坏标注就能把模型带偏且无人察觉。

### 1.3 训练数据永远来自人，不来自模型自己
模型建议被采纳后，入库的是**老师傅确认过的最终参数**（`is_ground_truth` 由复核决定），
不是模型原始输出。这切断自我强化的回声室——否则模型会越来越相信自己的历史偏差。
统计表述：标签生成过程始终独立于被评估的模型。

### 1.4 多炉共享 = 中心汇聚 + 本炉验证（双重门）
各炉数据包（带 `furnace_id`）经自有通道上自家受控云 → 中心在跨炉混合分布上重训 →
模型包分发 → 每台炉用**本炉留存样本**再过一次门（`activate`）才激活。
中心模型是混合分布上的估计；炉侧激活门就是在目标分布上做外部验证——中心再好，本炉验证不过就不上岗。
炉子身份从第一条数据就带着（ArchiveSample v2），炉子多了可升级分层建模（炉 = 随机效应分组因子）。

**安全边界始终在环外**：constraints 规则不参与迭代、不进权重；模型怎么变，出参都过同一道闸门（规则 > AI）。

## 2. 上炉流程：装到一台钢化炉后，到"可用"要经历什么

类比：调参师傅入职新厂——先认设备、再跟班学习、然后试用期考核、最后才独立给建议。

| 阶段 | 量级 | 内容 | 出口条件 |
|---|---|---|---|
| **0 开机即有** | 第 1 天 | 规则层立即工作：参数合规校验、国标判级、工艺问答、对话壳查询。**凡"产出参数"的功能都被闸门拦着**（缺值不放行，设计行为） | — |
| **1 建身份与接线** | 周级 | **跑初始化向导 `tools/furnace_setup.py`**（问答式录入炉号/分区/风机/型号/**投产与大修日期**，自动写 furnaces.yaml+sync.yaml 并打印检查清单）；对接扫描仪+图像↔标注对齐约定；导入本炉基准配方库；**核对本炉限值**（与他炉不同型不能照抄）填 `thresholds.yaml` | 安全真值齐（清单 A3–A6 同族） |
| **2 冷启动** | 与阶段3并行 | 零数据期 agent 只当**草稿助手**：Teacher 14B 产参→闸门→中文呈现→老师傅拍板，逐条人工复核。中心已有他炉模型可 `import-model`，但**不许直接用**——等本炉留存样本过第二重门 | — |
| **3 攒数据** | 月级 | 标注/复核 → `ingest_annotations --furnace-id Fx` 入库 → 按桶看板盯覆盖（深覆盖 4–6 个高产量桶）。前 20–30 条机械执行 Δ 字段预注册判据（`training.yaml: delta_review`） | ≥30 条起训（不足诚实拒训）；目标 200 |
| **4 首训与影子运行** | 试用期 | `train_param_head` → 候选登记 → 第一重门晋级 → **影子运行**：建议只显示不下发，与老师傅实际操作并排对比（按桶 MAE + 违规率）→ 认可后 `activate-model` 过第二重门 | 两重门 + 老师傅认可 |
| **5 常态运行** | 持续 | 人在环出建议、出炉实测回灌 `measured_*`、周期重训走版本门、数据包定期上云参与全网共享——回到 §1 环路 | — |

### "可用"的三个硬条件（缺一不可）
1. 本炉安全真值已填 → 闸门能放行；
2. 本炉留存验证过了第二重门 → 模型在本炉分布上被外部验证过；
3. 老师傅在影子期认可建议质量 → 人在环的最终裁定。
