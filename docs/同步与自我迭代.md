> 回答"Student 怎么持续变好、多台炉怎么共享数据与模型"。2026-07-02 拍板：**中心汇聚·文件包先行**——
> 各炉导出统一数据包 → 中心汇聚重训 → 分发模型版本；文件包链路**零联网依赖**（U盘/内网共享即可跑通），
> HTTP 云上传只留接口，云端信息到位并过安全评审后再补（见《信息需求清单》板块 C）。

## 1. 自我迭代闭环（一台炉视角）

```
老师傅标注/复核 → ingest_annotations 入库(data/archive, 带 furnace_id)
      │
      ├─(本炉自训) train_param_head → checkpoint(含契约指纹)
      │       → model_registry.register_candidate → promote(第一重门)
      │
      └─(多炉共享) sync_cli export-data → 数据包 → 自有通道 → 中心
              中心: import-data 汇聚多炉 → 重训 → register + promote(第一重门)
              → export-model → 模型包 → 分发各炉
              各炉: import-model(校验哈希+契约指纹) → activate-model(第二重门) → 生效
```

## 2. 包格式规范（schemas/datapack.py 为契约单一来源）

### 数据包 `datapack_<furnace_id>_<UTC时间戳>.zip`
```
manifest.json          # DataPackManifest：pack_id、furnace_id、archive_schema_version、
                       #   samples[]（sample_id + furnace_id + content_sha256）、producer
samples/<id>.json      # ArchiveSample 原样字节（哈希即对此字节算）
images/<sha256>.<ext>  # 可选（--include-images）
```

### 模型包 `modelpack_<model_id>.zip`
```
manifest.json          # ModelPackManifest：weights_sha256 + feature_schema_sha256 +
                       #   delta_fields_sha256（契约指纹）+ 中心侧门指标/结论
weights.pt             # 参数头权重
model_card.json        # 登记卡（指标与哈希，无配方数值）
```

## 3. 防错四道锁

| 锁 | 机制 | 出错时行为 |
|---|---|---|
| 版本锁 | manifest.archive_schema_version > 本地 `ARCHIVE_SCHEMA_VERSION` | 整包拒收，提示先升级代码 |
| 篡改锁 | 逐样本/权重 sha256 与 manifest 比对 | 该样本/整包拒收 |
| 冲突锁 | 同 (furnace_id, sample_id) 内容不同 | 上报 conflicts，**绝不静默覆盖**，人工裁决 |
| 契约锁 | 模型包指纹 ≠ 本地 FEATURE_NAMES/DELTA_FIELDS 指纹 | 拒收——特征列错位的模型比没有模型更危险 |

## 4. 双重版本门（规则 > AI 在模型分发上的延伸）

- **第一重（中心晋级 `promote`）**：`evaluate_param_gate` passed（出参零违规 + MAE 达标）
  且样本量 ≥ `min_train_samples` 且相对上一晋级版本不回归（容差 `gate.regression_tolerance`，
  均在 `config/training.yaml`）。结果如实记账（promote / promote_rejected）。
- **第二重（炉侧激活 `activate`）**：导入模型包后，用**本炉本地留存验证样本**
  （时间序尾部 val+test 段）再跑一次门，通过才激活——防"中心数据分布 ≠ 本炉分布"的静默回归。
  统计视角：中心模型是跨炉混合分布上的估计，炉侧激活门就是本炉分布上的外部验证集检验。
- 账本：机器读 `models/registry/registry.jsonl`（gitignore）；人读 `MODELS.md`（入 git，只有指标与哈希）。

## 5. 机密边界（红线）

- 数据包**内含配方**（params/baseline_params）→ 与填好的标注表同级：**绝不入 git**
  （`data/outbox/`、`data/inbox/` 已 gitignore），只经**工厂自有通道**流转、只上**自家受控云**。
- 模型包与 MODELS.md 只有权重、指标与哈希，无配方数值，密级低一档。
- 出厂字段范围**已拍板（2026-07-02，清单 C5）：全量含自由文本**——rationale/工况备注随包上云，
  诊断类目专项依赖这些文本做聚类；前提不变：仅工厂自有通道 + 自家受控云。
- 传输加密/落盘加密未做（与《产品形态与安全》§4.C 空白项同批），文件包阶段靠通道物理受控。

## 6. Runbook（PowerShell；$py = venv python）

```powershell
# ---- 炉侧：导出本炉数据包（落 data/outbox/）----
& $py tools\sync_cli.py export-data --furnace-id F1
& $py tools\sync_cli.py push data\outbox\datapack_F1_xxx.zip     # 经 drop_dir 投递（config/sync.yaml）

# ---- 中心：收包、汇聚、重训、登记、晋级、分发 ----
& $py tools\sync_cli.py pull                                     # 收进 data/inbox/
& $py tools\sync_cli.py import-data data\inbox\datapack_F1_xxx.zip
& $py training\train_param_head.py --archive data\archive --out runs\param_head
& $py tools\sync_cli.py register-model runs\param_head           # 登记候选（MODELS.md 记"候选"）
& $py tools\sync_cli.py promote-model param_head-v0001           # 第一重门（过则记"晋级"）
& $py tools\sync_cli.py export-model param_head-v0001

# ---- 炉侧：导入模型包 → 本地第二重门 → 激活 ----
& $py tools\sync_cli.py import-model data\inbox\modelpack_param_head-v0001.zip
& $py tools\sync_cli.py activate-model param_head-v0001
& $py tools\sync_cli.py status                                   # 看板：按炉/按桶/当前版本
```
