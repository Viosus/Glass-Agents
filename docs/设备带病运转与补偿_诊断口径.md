# 带病运转与元件补偿 · 诊断口径（三态）

> 现场知识来源：2026-07-03 用户口述（老师傅实践）。本文是逆向诊断"三态口径"的正文。
> 相关拍板（同日）：落地范围=文档+结构占位；登记表=单独轻量表（不动 39 列契约）；
> 补偿实践**会超出 C1 限值**（现场口径录入前闸门照拦）。
> `.claude/rules/项目架构说明.md` 的逆诊断段引用行待并行占用解除后补。

## 1. 现场事实（不可推翻的输入）

- **参数调对 ≠ 炉温到位**：炉内元件（加热元件等）损耗后，实际温度达不到设定值是常事。
- **老师傅的标准补救**：调高损耗元件**邻近元件**的参数，实践证明可行、质量不大幅下降。
- **周保养节拍固定**：元件本就每周保养；再缩短周期成本吃不消 → **带病运转是工业常态，不是异常**。

## 2. 诊断类目：二分 → 三态

原口径「炉子坏了 / 参数没调好」隐含"参数偏离基准 = 有问题"，与现场事实冲突。改为三态：

| 态 | 定义 | 判定线索（候选，D3 专项敲定，不臆造阈值） |
|---|---|---|
| ① 健康 | 元件正常，参数按工艺需求设定 | 参数贴近基准 + 质量正常 |
| ② 带病已补偿 | 元件损耗存在，邻区参数补偿到位 | **补偿签名**：参数空间局部凸起（某区设定相对基准/邻区异常抬高）+ 质量正常 |
| ③ 带病未补偿 / 补不动 | 损耗未被补偿或补偿失效 | 质量残差异常（应力斑分布劣化），伴或不伴参数凸起 |

态② = **常态且可接受，不报"故障"**。它的诊断价值不是报警，而是：识别"哪个元件正在被补偿"
→ 进下次周保养的优先检查清单（见 §3.2）。

## 3. 对各条线的影响

### 3.1 归因线（advisor/attribution）
- `config/attribution.yaml` 注释区已预留**补偿签名规则结构**（真值 TODO(plant)，阈值待 D3/E4 专项 + A11 口径）。
- 预约定信号键名：`zone_setpoint_bump_c` = 某区设定值相对基准配方/邻区中位的抬高幅度（℃），由调用方组装进信号字典。
- 命中态②时产出应指向**维保检修清单**，不作故障告警。

### 3.2 维保线（advisor/maintenance）
- `service_items` 的定位 = **"下次周保养优先查哪个元件"**，不是建议缩短保养周期（成本约束下节拍固定，缩周期方案现场不接受）。
- `est_hours_to_service` 同理是排期提醒，非催修命令（标注说明 §9 已有此口径）。
- **补偿幅度本身 = 元件健康度的免费观测**：周保养（换件/修复）前后的参数轨迹是天然标签源——
  补偿量随损耗单调爬升、保养后回落。B4（PLC/MES 取数）到位后即可利用，**无需故障标签**。

### 3.3 参数头训练（混杂控制）
- 老师傅的最终参数 = **工艺需求 + 设备补偿**两种成分混合。不记录设备状态就是遗漏变量偏倚：
  模型会把补偿量学成工艺规律，推到健康炉上产生系统性偏差。
- 处置（2026-07-03 拍板）：不动 39 列契约；**单独轻量《元件问题登记表》**（`docs/元件问题登记表.md`），
  按**日期+时段**与标注表对齐。
- 训练时的用法（统计口径）：先把"补偿期样本"当**分层变量**做敏感性分析（含/不含补偿期各训一版比较），
  效应显著再考虑把设备状态升为输入特征；不预先删数据。
- 入库无阻：`tools/ingest_annotations.py` 对闸门违规**只记录不拒收**（既有行为），补偿样本不会被挡在库外。

### 3.4 残差异常检测口径修正
- 质量残差正常 **≠** 设备健康（补偿会掩盖损耗）。
- 参数残差大 **≠** 失调（可能是合理补偿）。
- 「炉子坏了/元件损耗」的检测量 = **质量残差 ∧ 参数补偿形态 联合判断**，任何单量都会误判。

## 4. C1 冲突（已确认，红线处理）

- 现场确认（2026-07-03）：补偿实践**会超出** C1 的"相邻分区温差≤5℃ / 单次调温≤±3℃"。
- 处理：**闸门照拦、不放宽**（"不得自动放宽"是安全红线；被拦 ≠ 师傅操作错误，是补偿模式的
  限值口径尚未录入）。后果与解释：
  - 补偿场景的参数单会显示 ⛔ 未通过——系统只显示不下发，不影响师傅实际操作；
  - 标注入库不受影响（§3.3 只记录不拒收）；
  - 训练库中"最终参数未过闸门"的行是**合法样本**，不是脏数据。
- 待办：**信息需求清单 A11**——补偿模式下的 C1 限值口径（允许的最大补偿温差/调温步长、
  适用条件），工艺+维修专项确认，建议与 D3 诊断类目座谈同场。口径到位后先修订
  `config/thresholds.yaml`；若需"补偿模式"分支逻辑再动 `tools/constraints.py`，须过评审。
