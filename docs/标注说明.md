# 老师傅工作说明（标注 · 复核 · 看单）

> 这份文档只回答一个问题：**老师傅要干什么、怎么干**。除填标注表外，复核建议、看参数单、
> 看研判报告、出炉回填、提供炉子底账，全部收在这一份里。
> 标注表由 `tools/make_annotation_template.py` 生成（`data/annotation/标注表模板.xlsx` / `.csv`），
> 列与 `schemas.ArchiveSample` 对齐，导入即校验（脏行拒收）。
> 更新日期：2026-07-03。

## 1. 标注表怎么填（一句话）
系统/记录员先填好 **A 标识、B 规格、C 状况、D 基准配方（只读参考）**；老师傅只动 **E 最终参数**（在预填基准上改要动的项）、**F 主观判级**、**G 理由**。出炉后再补 **I outcome**。

打开 xlsx 认颜色就行（2026-07-03 版式）：
- **黄色 ★ 列 = 你填**（最终参数/目测判级/理由）；**浅蓝列 = 出炉后补**；**灰色列勿动**（系统/记录员的，已默认折叠——需要看时点列上方 `+` 展开）。
- **第 2 行是中文说明行，勿删**（导入时系统自动跳过它）；真数据从第 5 行起写（3–4 行灰斜体是示例）。

## 2. 红线（务必遵守）
- **缺值不猜**：没有的量（IsoT/CCP、工况细项、成因类目）**留空**或写 `TODO(plant)`，**绝不填占位数字**。
- **单位固定**：温度 ℃、时长 s、厚度 mm、光程差 nm；表头后缀 `_c/_s/_mm/_nm` 已标明，只填数值。
- **枚举照选**：`glass_type∈{ultra_clear,clear}`、`quality_mode∈{high_quality,high_efficiency}`、判级 `∈{A,B,C}`（xlsx 有下拉）。
- **等长非空**：`final_zone_temps_c` 与 `final_zone_roles` 用分号 `;` 隔、**个数必须相等**（如 `705;708;700` 配 `center;center;edge`）。
- **主观 ≠ 实测**：`expert_quality_grade` 是你目测判级；`measured_quality_grade` 是出炉实测，现在**留空**，别混。

## 3. 分组与谁填
| 组 | 谁填 | 要点 |
|---|---|---|
| A 标识 | 记录员/系统 | sample_id 唯一；operator_id 记你的工号（用于核对标注一致性） |
| B 规格·分桶键 | 记录员 | 厚度/品类/模式——决定分层，务必准确 |
| C 输入·状况X | 系统 | X0.95 有则填；IsoT/CCP 暂无→留空；有应力斑图填路径+sha256 |
| D 基准配方 | 系统预填(只读) | 现场用**真实基准配方**替换模板示例值 |
| E 最终参数 | **老师傅** | 预填=基准，**只改要动的项**；改哪些不限（含分区温度） |
| F 主观判级 | **老师傅** | 目测该片质量 A/B/C |
| G 归因 | **老师傅** | 中文写清**为什么这么调**（将作归因弱标签）；成因标签类目未定→留空 |
| H 复核·一致性 | 记录员 | is_ground_truth 默认 TRUE；重复标注见 §5 |
| I outcome | 后补 | 出炉后按 sample_id 回填实测质量/能耗 |

## 4. 分层目标（保证 200 份能训）
- **桶 = 厚度 × 品类 × 质量模式**。
- **深覆盖少数桶 优于 薄铺满所有桶**：把 200 份集中在**产量最高的 4–6 个桶**，每桶 ~30–50 条。
- 建议按现场产量填下表后照此配额（示例）：

| 桶(厚度/品类/模式) | 目标条数 |
|---|---|
| 8mm / clear / high_quality | ~50 |
| 8mm / clear / high_efficiency | ~40 |
| 10mm / clear / high_quality | ~40 |
| 6mm / ultra_clear / high_quality | ~40 |
| （现场按产量补/调） | ~30 |
| **合计** | **~200** |

## 5. 一致性重复（测标注稳定性）
- 挑 **10–15 个情形**，**隔时（如次日）再标一次**，两行用**相同 `repeat_group_id`**（如 `R01`）。
- 用于评估同一老师傅前后标注的方差，便于统一口径。

## 6. 何时算"可训"
- 一行计入训练需 **B/C 输入齐 + E 最终参数齐**；缺任一只作占位。
- 参数头标签 = `Δ = 最终 − 基准`（系统自动算）。**你只管在基准上改**，Δ 我们来算。
- 导入命令（记录员/我方，标注积累后运行）：`python tools/ingest_annotations.py <填好的表.csv>` → 入库并打印各桶覆盖看板。

## 7. 复核系统建议：草稿是它的，决定是你的

**现阶段（数据少）**——系统只当**草稿助手**：它产的参数先过安全闸门，再以中文呈现给你。
- 你可以采纳、改动或整个否掉；**你确认后的最终参数**才写进标注表 E 组（这才是训练用的真值）。
- 系统**永远不会自动改炉子**——所有建议只显示，改不改、改多少由你在操作台上动手。

**首训之后（影子期）**——系统建议只显示不下发，和你的实际操作**并排对比**：
- 技术员会按桶统计"建议 vs 你的操作"的差距和违规率给你看；
- **你认可建议质量、签字后系统才转正**（第二重门）；你不点头它不上岗。

三条铁规矩（系统侧已写死，你知道即可）：
1. 所有数字来自确定性计算，聊天模型不产数字；
2. 每组参数下发前必过安全闸门，越限的只报问题、不给"照做"建议；
3. 训练数据永远来自你确认过的操作，不来自系统自己的历史输出（防自我强化跑偏）。

## 8. 参数单怎么看（Excel，`data/outbox/参数单_*.xlsx`）

对话里说「导出参数单」即可生成；打开先看**头部第 4 行**：

| 头部显示 | 含义 | 你该怎么办 |
|---|---|---|
| **✅ 通过** | 全套参数过了安全闸门 | 可作参考执行（仍以你判断为准） |
| **⛔ 未通过——禁止照此操作** | 有越限项 | **绝不照做**；下方"问题清单"逐条列了原因 |

- 参数表列：中文名 / 当前值 / 单位 / **基准值** / **Δ**（相对基准改了多少）——你只需要重点看 Δ 非零的行。
- 分区温度逐区展开（分区1/分区2/…，带 center/edge 角色）。
- ⚠️ 现在本炉安全限值还没录全（见 §10），闸门**全拦是正常现象**——不是系统坏了，是"缺真值不放行"的规矩；限值录入后自动解锁。
- ⚠️ 你为补元件损耗**调高邻区参数**导致的 ⛔ 也属正常（补偿场景的限值口径还没录入，系统先保守拦）——**不代表你操作错误**，照你的判断操作炉子即可，同时记得在《元件问题登记表》记一行。

## 9. 研判报告怎么看（六项，技术员生成打印）

系统能出一份研判报告，六个板块：**工艺参数 / 能耗 / 设备维保 / 摆炉排布 / 缺陷归因 / 光学特征**。
看的时候记住三条：

1. **"无法判定：缺××"不是故障**——对应的真值/数据还没录入，系统按规矩不编数。缺什么它列什么，录入后自动点亮。
2. **带"（未标定参考值，不当真值）"的数字只能看趋势**，不能当准数用——比如能耗估计，标定前只用于"这次比上次高还是低"。
3. **维保板块是外推估计**："老化度 xx%""预计再运行 xxh 达检修阈值"按当前换产节奏线性外推；**安排检修前仍以现场点检为准**，报告是提醒不是命令。报告点名某元件"建议检修"，意思是**下次周保养时优先查它**——不是让你加保养次数、缩保养周期。

缺陷归因板块给的是"疑似原因 + 触发证据"线索（如"边部温度偏低 ← 相邻分区温差超限"）；
疑似分区定位暂缺（等分区邻接关系录入），别期望它现在能指到具体哪个区。

## 10. 交炉子底账（上炉时一次性，交给记录员录入）

记录员会跑初始化向导（`tools/furnace_setup.py`）逐项录入，你需要提供或指路：

| 项 | 哪里找 | 用处 |
|---|---|---|
| 炉子型号 / 厂家 | 铭牌 | 炉子身份档案 |
| 分区数量 / 排布 / 风机数 | 铭牌或说明书 | 分区温度表结构 |
| **投产日期** | 设备台账 | **炉龄特征的唯一原料，别跳过** |
| **上次大修日期** | 维修记录 | 老化建模 |
| 本炉安全限值（相邻分区温差上限/单次调温上限/炸板规则等） | 厂方工艺文件（谁有你指路） | **闸门解锁的钥匙**（§8 的 ⛔ 全拦就卡在这） |

不知道的项**直接说不知道**（向导里回车跳过），系统按缺失记录——比填个大概数强一百倍。

- 数据只上**自家受控云**参与多炉共享，通道由我方与厂方共同确认后才开通（当前未开通）。
